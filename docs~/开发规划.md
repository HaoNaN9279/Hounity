# Hounity 开发规划

> 依据 [设计方案](设计方案.md) 制定的实施计划。目标：构建基于 GraphView 的节点化 HDA 工作流系统。

## 一、目标与范围

**总目标**：在 Unity 编辑器内实现节点化 HDA 工作流，支持多 HDA 节点与工具节点连线组合，产出离线资产，且不阻塞主线程。

**范围**：
- 节点图编辑器（GraphView）、数据模型与序列化。
- 工作流引擎（依赖排序、全量/增量 Cook、缓存）。
- 节点实现（HDA / 选择器 / Mesh 工具 / 预览 / 输出）。
- 多任务管理器与 Session 管理。
- 编辑期工具链，不含运行时播放逻辑。

**非目标**：替换 Houdini Engine Core；实现 HAPI 底层；运行时（Play 模式）工作流执行。

## 二、技术栈与前置条件

| 项 | 选型 |
|---|---|
| 引擎 | Unity 2022.3（GraphView API 建议封装适配层） |
| 图框架 | `UnityEditor.Experimental.GraphView` |
| HDA 执行 | Houdini Engine for Unity（HEU API：Asset 层 + Utility 层） |
| 并行计算 | Unity Job System + Burst Compiler |
| 凸分解 | VHACD（Native Plugin / 内置库） |
| 数据持久化 | ScriptableObject |

**前置条件**：安装并验证 Houdini Engine for Unity 插件、可用的 Houdini Engine 许可证、准备测试 HDA 资产。

## 四、里程碑与阶段

### 阶段一：基础框架（M1）

**目标**：打通「HDA 节点 → Cook → 输出资产」最小闭环。

- GraphView 编辑器窗口与基本交互（建节点、连线、拖拽）。
- `WorkflowGraphSO` / `BaseNodeSO` / `PortSO` 数据模型。
- 独立边列表的序列化与反序列化（不依赖 GraphView 自身序列化）。
- `HDANodeSO`：加载 HDA、读取暴露参数、映射为编辑器字段、写回并触发 Cook。
- `OutputNodeSO`：输出 Mesh / Prefab / ScriptableObject / JSON。
- HDA Session 初始化与同步 Cook 调用。

**验收**：单个 HDA 节点参数改动后可 Cook 并输出资产；图保存后重开连接与参数完整恢复。

### 阶段二：核心节点（M2）

**目标**：补齐节点类型与后台执行、任务管理。

- 资源选择器节点：单资源 `ObjectField` + 多资源命名过滤（Contains / StartsWith / EndsWith / Regex）。
- GameObject 选择器节点：父子递归、按命名、按组件字段值（条件表达式解析）。
- 预览节点：`PreviewRenderUtility` 离屏渲染 + 旋转/缩放/平移 + 直通输出。
- 工作流引擎：DAG 构建、拓扑排序、依赖执行。
- 异步 Cook（`Async = true` + 完成回调）接入。
- Job System 后台计算与分帧主线程操作。
- 多任务管理器：Session 池、任务队列、进度显示、取消。

**验收**：多节点工作流可正确按依赖执行；Cook 期间主线程可交互；任务面板实时反映状态并可取消。

### 阶段三：Mesh 工具（M3）

**目标**：实现三个 Mesh 工具节点。

- LOD 生成：优先 Unity 内置 LOD 生成器，保留 QEM 自定义路径（Job 并行边折叠）。
- ShadowProxy 生成：大幅度简化（目标面数 5%–10%）+ 内部面移除。
- CollisionMesh 生成：凸包模式、VHACD 分解模式、简化代理模式。
- 输出 LODGroup 配置数据与 Collider 配置。

**验收**：三节点在测试 Mesh 上产出正确结果；LOD 各级面数递减符合预期；VHACD 复合碰撞体可用。

### 阶段四：优化与交付（M4）

**目标**：性能、缓存、可用性与文档。

- 增量 Cook：基于参数哈希跳过未变化节点。
- 缓存管理：HDA 输出磁盘缓存（键 = HDA 路径 + 参数哈希）。
- 暴露参数系统：`Workflow → Node → Parameter` 三级映射。
- Workflow 嵌套引用。
- 多任务管理器并发调度与取消完善。
- 大规模节点图优化：视图懒加载、增量保存、大输出外置。
- 文档与示例工作流。

**验收**：参数微调仅重算受影响子图；复杂图（100+ 节点）交互流畅；示例工作流可复现。

## 六、关键技术风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| HAPI Session 非线程安全 | 并发调用崩溃/数据错乱 | 所有 HAPI 调用序列化到主线程，实现调用队列 |
| GraphView 为 Experimental API | 升级后破坏 | 引用集中到适配层，便于迁移 Graph Toolkit |
| 多连接 Port 序列化丢连接 | 图还原错误 | 独立边列表维护连接，不依赖 GraphView 序列化 |
| 大规模图性能瓶颈 | 编辑卡顿 | 视图懒加载、增量保存、大输出外置 |
| Houdini 许可证限制 | Session 数量受限 | Session 池复用，队列排队调度 |
| VHACD 集成复杂度 | 碰撞体生成不稳 | 优先 Native Plugin 封装，提供回退简化代理模式 |

## 七、测试与验证策略

- **EditMode 测试**：数据模型序列化/反序列化、参数映射、命名过滤、条件表达式、DAG 拓扑排序、参数哈希。
- **PlayMode / 编辑器测试**：HDA Cook 闭环、任务队列、取消机制、Mesh 工具输出。
- **性能测试**：大图交互帧率、增量 Cook 命中率、后台计算主线程占用。
- **手工验收**：示例工作流端到端产出离线资产。
